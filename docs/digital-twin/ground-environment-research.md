# 3D 디지털 트윈 바닥(도로·보도·차도) 환경 탐구

목표: 도면 5(1/1,000 블록, 층 슬래브 단위 공실 색)처럼, 공실 주변 바닥(차도·보도·횡단보도)을 표현하고 서울 구 단위로 공실을 구별한다. 현재 트윈은 절차 생성 격자 도시(`BuildingTwin.tsx`, "데모 데이터")다.

## 확인된 사실 / 미확인
- 네이버 지도 JS v3는 벡터 지도, GeoJSON·KML·GPX 데이터 레이어, 사용자 정의 레이어를 제공한다(NCP 문서).
- **미확인(반드시 약관 확인)**: 네이버 지도 타일·화면을 캡처해 3D 텍스처로 쓰거나 도로 도형을 추출하는 것이 허용되는지. 검색으로 조항을 확인하지 못했다. 허용 전제로 설계하지 않는다.
- 서울시 S-Map 오픈랩은 서울시 보유 공간정보 200여 종(도로면 등)을 가입만으로 제공하고 QGIS 연계를 지원한다고 소개된다. 브이월드(국토부)는 3D 지도·공간정보를 제공한다. 데이터별 라이선스·좌표계·갱신일은 개별 확인이 필요하다.
- OSM은 `highway=footway`, `footway=sidewalk`, `sidewalk=*` 태그로 보도를 표현하지만 폭 정보가 대체로 부족하다. ODbL 표기 의무가 있다.

## 방법 비교
| # | 방법 | 현실성 | 장점 | 위험 |
|---|---|---|---|---|
| A | 네이버 지도를 바닥 텍스처로 사용 | 낮음 | 즉시 예쁨 | 약관·갱신·해상도, 3D 정합 어려움 |
| B | 네이버 지도는 2D 선택 UI로 유지, 3D 바닥은 공공 벡터로 생성 | **높음 (권장)** | 라이선스 명확, 도형 제어 가능 | 데이터 전처리 필요 |
| C | OSM 도로·보도 선 → 폭 규칙으로 면 생성 | 중간 | 즉시 시작, 무료 | 폭 추정치(표시 필요), 누락 |
| D | MapLibre/deck.gl 등으로 틸트 3D 지도 + 건물 extrude | 중간 | 타일·LOD 내장, 층 슬래브 색 표현 쉬움 | 현 three.js 트윈과 이중 구조 |
| E | 구 단위 사전 가공 타일(GeoJSON→간략 메시) + LOD | 중간 | 서울 전역 확장 | 파이프라인 구축 비용 |

## 권장안 (B + E, C는 보완)
1. **바닥 데이터**: 서울시/브이월드의 도로면·보도·횡단보도·건물 외곽 → 구별 GeoJSON으로 전처리(`tools/print3d/coordinates.py`의 미터 좌표 변환 재사용). 없는 구간만 OSM으로 보완하고 출처를 속성에 기록한다.
2. **면 분류**: `carriageway`(차도) / `sidewalk`(보도) / `crosswalk` / `block`. 폭을 추정한 면은 `estimated=true`로 표시한다(도면 5의 "반투명=높이 추정" 규칙과 동일).
3. **공실 표시**: 층 슬래브 단위로 `confirmed`=빨강, `probable`=주황, 그 외 회색(도면 5 범례). 현재 트윈은 certainty 구분이 없으므로 `/floors` 응답에 `certainty` 추가가 필요하다(API 계약 변경 → 담당자 승인).
4. **서울 구 구별**: `seoulBoundaries.ts`의 구 경계로 바닥에 구 외곽선과 구별 색조, 구 단위 공실률을 바닥 히트맵 데칼로 표시. 네이버 지도에서 구 선택 → 트윈으로 이동(마커 ID 연동).
5. **LOD**: 반경 200m는 상세(차도/보도/횡단보도/가로수), 1,000m까지는 블록 외곽만.
6. **출력 연계**: 같은 바닥 면으로 1:1,000 베이스 플레이트(도로 홈 0.4mm 등)를 STL로 내보내 실물 모형과 화면을 일치시킨다(`export_mesh.py` 확장).

## 단계
- P0(1~2일): 약관·라이선스 확인표 작성(네이버, S-Map, 브이월드, OSM), 시범 구 1곳 선정.
- P1(1주): 시범 구 바닥 GeoJSON 생성 + 트윈에 차도/보도 면 렌더, "추정" 표시.
- P2(1주): certainty 슬래브 색, 구 경계·공실률 데칼.
- P3: 서울 25개 구 확장(타일 사전 가공), 성능 측정(기기·프레임 기준을 먼저 정의).

## 열린 질문 (소유자 결정)
네이버 약관 해석, 바닥 데이터 1차 출처, 폭 추정 허용 여부, API에 certainty 추가 승인.
