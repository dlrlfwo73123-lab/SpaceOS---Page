# 5·6·7단계 계획 (구현하지 않음)

## 5. 도면·LiDAR 실측 승격
- 실측 승격 조건: 도면 참조·측정일·측정자·정밀도가 모두 있을 때만 `measured` (`evidence.classify_geometry`).
- 필요한 입력: 허락된 도면/스캔, 기준 치수. 없으면 `unverified`로 보고한다. LiDAR라는 이유만으로 `accuracy_m`을 넣지 않는다.
- 별도 승인 후 Bronze/Silver/Gold 경로를 추가한다.

## 6. 슬라이싱·시험 출력
- 3단계 STL을 슬라이서에 불러 bounding box, 파트 배치, 두께, 서포트를 확인한다.
- 작은 시험편을 먼저 출력하고 실측 치수·사진을 목표값과 비교한다. 예상값과 실제값은 따로 기록한다.
- 기준 프로필 없이 G-code를 만들지 않는다.

## 7. PlaceOS 연동 제안
- 현재: `/buildings/{id}/model`이 `demo-building` 하나만 GLB를 반환하고 나머지는 404다. 프론트 `BuildingTwin.tsx`가 이를 소비한다.
- 제안: 출력용 STL과 별개로, 웹 표시용 GLB를 건물 ID에 등록하는 방식. 파일이 없으면 성공 응답을 만들지 않는다(기존 404 유지).
- 응답에 unit ID·버전·출처·실측/제안 구분을 담는 계약은 담당자 승인 후 정한다. 앱 코드는 승인 전에 수정하지 않는다.
